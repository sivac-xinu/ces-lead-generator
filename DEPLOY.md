## 1. Architecture Overview

```
┌──────────────────────────────────────────────────────────────────┐
│                      Frontend (React)                            │
│   Vite + React 19 + TypeScript + Tailwind CSS                   │
│   React Query (server state) + Zustand (UI state)               │
│   Deployed to: GitHub Pages / Netlify / Vercel / any static host│
└──────────────────────────┬───────────────────────────────────────┘
                           │
              ┌────────────▼────────────┐
              │   Adapter Layer          │
              │   (DB + Auth + API)      │
              └──┬──────────────────┬───┘
                 │                  │
    ┌────────────▼────┐   ┌───────▼────────────┐
    │  Supabase       │   │  Custom Backend     │
    │  (default)      │   │  (REST API)         │
    │                 │   │                     │
    │  PostgreSQL     │   │  PostgreSQL         │
    │  + RLS          │   │  + JWT Auth         │
    │  + Edge Fns     │   │  + Express/Node/etc │
    └────────┬────────┘   └───────┬────────────┘
             │                    │
      ┌──────▼──────┐     ┌──────▼──────┐
      │ External    │     │ External    │
      │ AI APIs     │     │ AI APIs     │
      │ ZoomInfo    │     │ ZoomInfo    │
      └─────────────┘     └─────────────┘
```

**Key facts:**
- The frontend is a **static SPA** (no server needed). Hosted on GitHub Pages, Netlify, Vercel, or any static host.
- **Adapter pattern**: The app abstracts all database, auth, and API calls behind pluggable adapter interfaces.
- **Two built-in backends**:
  - `supabase` (default) — uses Supabase PostgreSQL + Edge Functions + RLS.
  - `rest` — uses any REST API server you build. The adapters define the expected API contract.
- Set `VITE_DB_BACKEND` in `.env` to choose: `supabase` or `rest`.
- AI intelligence features require at least one AI provider API key (OpenRouter is easiest to start with).

## 3. Database Setup

### Supabase Backend (default)

#### 3.1 Create a Fresh Supabase Project

1. Go to [supabase.com](https://supabase.com) → New Project
2. Note your **Project URL** (e.g., `https://xxxxxxxx.supabase.co`)
3. Note your **Anon Key** (Settings → API → `anon` `public`)
4. Note your **Service Role Key** (Settings → API → `service_role` — keep secret)

### 3.2 Run the Full Schema SQL

Open **Supabase SQL Editor** and run the following SQL in order. This creates all tables, functions, triggers, RLS policies, and indexes from scratch.

#### Step 1: Create base tables

```sql
-- ============================================================
-- BASE TABLES (create all tables the application needs)
-- ============================================================

-- Leads: main lead records
create table if not exists public.leads (
  id                bigint generated by default as identity primary key,
  company           text not null,
  contact_name      text,
  contact_title     text,
  contact_email     text,
  contact_phone     text,
  industry          text,
  employees         int,
  company_size      text,
  location          text,
  website           text,
  linkedin_url      text,
  it_type           text default 'Unknown',
  current_infra     text,
  pain_points       text[],
  annual_it_budget  text,
  status            text default 'New',
  user_id           uuid references auth.users(id) on delete set null,
  imported          boolean default false,
  imported_by       text,
  company_source    text,
  sales_rep         text,
  assigned_rep      text,
  icp               text,
  tier              text,
  notes             text,
  created_at        timestamp with time zone default now(),
  updated_at        timestamp with time zone default now()
);

-- Contacts: multiple contacts per lead
create table if not exists public.contacts (
  id         bigint generated by default as identity primary key,
  lead_id    bigint not null references public.leads(id) on delete cascade,
  name       text not null,
  title      text,
  email      text,
  phone      text,
  is_primary boolean not null default false,
  source     text,
  created_at timestamp with time zone default now(),
  updated_at timestamp with time zone default now()
);

create index if not exists idx_contacts_lead_id on public.contacts(lead_id);

-- Call logs: call tracking pipeline
create table if not exists public.call_logs (
  id               bigint generated by default as identity primary key,
  lead_id          bigint references public.leads(id) on delete cascade,
  rep              text,
  date             text,
  outcome          text,
  notes            text,
  next_action_date text,
  follow_up        text,
  company          text,
  contact_name     text,
  contact_title    text,
  user_id          uuid references auth.users(id) on delete set null,
  created_at       timestamp with time zone default now()
);

-- Solutions: CES service catalog
create table if not exists public.solutions (
  id         text primary key,
  service    text not null,
  urgency    text,
  icon       text,
  keywords   text[],
  trend      text,
  buy_signal text,
  pitch      text,
  stat       text,
  created_at timestamp with time zone default now()
);

-- Profiles: user profiles (linked to auth.users)
create table if not exists public.profiles (
  id         uuid primary key references auth.users(id) on delete cascade,
  email      text,
  first_name text,
  last_name  text,
  role       text default 'user',
  approved   boolean default false,
  created_at timestamp with time zone default now()
);

-- Audit log
create table if not exists public.audit_log (
  id         bigint generated by default as identity primary key,
  user_id    uuid,
  action     text,
  detail     text,
  created_at timestamp with time zone default now()
);

-- Pain point catalog
create table if not exists public.pain_point_catalog (
  id         bigint generated by default as identity primary key,
  text       text not null,
  theme      text not null default 'General',
  tags       text[] default array[]::text[],
  active     boolean not null default true,
  created_at timestamp with time zone default now()
);

-- CES settings (stores shared AI API keys)
create table if not exists public.ces_settings (
  id         text primary key default 'global',
  ai_keys    jsonb default '{}'::jsonb,
  created_at timestamp with time zone default now(),
  updated_at timestamp with time zone default now()
);

insert into public.ces_settings (id, ai_keys)
values ('global', '{}'::jsonb)
on conflict (id) do nothing;
```

#### Step 2: Create helper functions and triggers

```sql
-- ============================================================
-- FUNCTIONS & TRIGGERS
-- ============================================================

-- Helper: check if the current user is an admin
create or replace function public.is_admin()
returns boolean as $$
begin
  return exists (
    select 1 from public.profiles
    where id = auth.uid() and role = 'admin'
  );
end;
$$ language plpgsql security definer;

-- Auto-create a profile row when a new user signs up
create or replace function public.handle_new_user()
returns trigger as $$
begin
  insert into public.profiles (id, email, first_name, last_name, role, approved)
  values (
    new.id,
    new.email,
    new.raw_user_meta_data->>'first_name',
    new.raw_user_meta_data->>'last_name',
    'user',
    false
  )
  on conflict (id) do nothing;
  return new;
end;
$$ language plpgsql security definer;

-- Trigger: runs after every auth signup
drop trigger if exists on_auth_user_created on auth.users;
create trigger on_auth_user_created
  after insert on auth.users
  for each row execute function public.handle_new_user();
```

#### Step 3: Enable RLS and create policies

```sql
-- ============================================================
-- ROW LEVEL SECURITY
-- ============================================================

-- Enable RLS on all tables
alter table public.leads enable row level security;
alter table public.contacts enable row level security;
alter table public.call_logs enable row level security;
alter table public.solutions enable row level security;
alter table public.profiles enable row level security;
alter table public.audit_log enable row level security;
alter table public.pain_point_catalog enable row level security;
alter table public.ces_settings enable row level security;

-- Leads: full CRUD for any authenticated user
drop policy if exists "Authenticated full access" on public.leads;
create policy "Authenticated full access" on public.leads
  for all using (auth.role() = 'authenticated')
  with check (auth.role() = 'authenticated');

-- Contacts: full CRUD for any authenticated user
drop policy if exists "Authenticated full access" on public.contacts;
create policy "Authenticated full access" on public.contacts
  for all using (auth.role() = 'authenticated')
  with check (auth.role() = 'authenticated');

-- Call logs: full CRUD for any authenticated user
drop policy if exists "Authenticated full access" on public.call_logs;
create policy "Authenticated full access" on public.call_logs
  for all using (auth.role() = 'authenticated')
  with check (auth.role() = 'authenticated');

-- Solutions: read for users, admin-only write
drop policy if exists "Authenticated read" on public.solutions;
drop policy if exists "Admin write" on public.solutions;
create policy "Authenticated read" on public.solutions
  for select using (auth.role() = 'authenticated');
create policy "Admin write" on public.solutions
  for all using (public.is_admin())
  with check (public.is_admin());

-- Profiles: read for users, admin-only write
drop policy if exists "Authenticated read" on public.profiles;
drop policy if exists "Admin write" on public.profiles;
create policy "Authenticated read" on public.profiles
  for select using (auth.role() = 'authenticated');
create policy "Admin write" on public.profiles
  for all using (public.is_admin())
  with check (public.is_admin());

-- Audit log: insert for users, read for admins
drop policy if exists "Authenticated insert" on public.audit_log;
drop policy if exists "Admin read" on public.audit_log;
create policy "Authenticated insert" on public.audit_log
  for insert with check (auth.role() = 'authenticated');
create policy "Admin read" on public.audit_log
  for select using (public.is_admin());

-- Pain point catalog: read for users, admin-only write
drop policy if exists "Authenticated read" on public.pain_point_catalog;
drop policy if exists "Admin write" on public.pain_point_catalog;
create policy "Authenticated read" on public.pain_point_catalog
  for select using (auth.role() = 'authenticated');
create policy "Admin write" on public.pain_point_catalog
  for all using (public.is_admin())
  with check (public.is_admin());

-- CES settings: admin full access, authenticated read
drop policy if exists "Admin full access" on public.ces_settings;
drop policy if exists "Authenticated read ai_keys" on public.ces_settings;
create policy "Admin full access" on public.ces_settings
  for all using (public.is_admin())
  with check (public.is_admin());
create policy "Authenticated read ai_keys" on public.ces_settings
  for select using (auth.role() = 'authenticated');
```

### Custom REST Backend

#### 3.1 Create Database

Use any PostgreSQL database (self-hosted, AWS RDS, Google Cloud SQL, etc.). Create the same tables as shown above, but without Supabase-specific RLS policies and `auth.*` functions.

The REST backend handles auth via JWT tokens in your server code rather than PostgreSQL RLS. Implement the API contract documented in [Section 5a](#5a-rest-backend-api-contract).

### 4.2 First Admin User

After deployment, you need to manually promote the first user to admin:

1. Sign up through the app (or Supabase Auth UI)
2. In Supabase SQL Editor, run:

```sql
-- Replace the UUID with the actual user's ID from auth.users
update public.profiles
set role = 'admin', approved = true
where id = '<USER_UUID>';

-- Also approve them
update auth.users
set raw_user_meta_data = raw_user_meta_data || '{"approved": true}'::jsonb
where id = '<USER_UUID>';
```

## 5. Edge Functions Deployment

> **Skip this section** if using `VITE_DB_BACKEND=rest` (custom REST backend).

The application has 3 Edge Functions in `supabase/functions/`:

| Function | Purpose | Required? |
|----------|---------|-----------|
| `ai-proxy` | AI intelligence (routes to OpenRouter/OpenAI/Claude/Gemini) | Yes (core feature) |
| `zoominfo-proxy` | ZoomInfo company search/enrichment | No (optional) |
| `admin-delete-user` | Admin user deletion | Yes (admin feature) |

### 5.1 Deploy via Supabase CLI

```bash
# Install Supabase CLI if not already installed
npm install -g supabase

# Link to your Supabase project
supabase link --project-ref <YOUR_PROJECT_REF>

# Deploy each function
supabase functions deploy ai-proxy
supabase functions deploy zoominfo-proxy
supabase functions deploy admin-delete-user
```

### 5.2 Deploy via Dashboard (Alternative)

If you don't have the CLI, you can paste each function's code directly in the Supabase Dashboard → **Edge Functions** → Create function.

Copy the code from:
- `supabase/functions/ai-proxy/index.ts` + `supabase/functions/ai-proxy/providers.ts`
- `supabase/functions/zoominfo-proxy/index.ts`
- `supabase/functions/admin-delete-user/index.ts`
- `supabase/functions/_shared/cors.ts` (imported by all functions)

### 5.3 Set Edge Function Secrets

In Supabase Dashboard → **Edge Functions → Secrets** (or via CLI):

```bash
# At least one AI provider key is needed for intelligence features
supabase secrets set OPENROUTER_API_KEY=sk-or-...

# Optional: additional providers
supabase secrets set OPENAI_API_KEY=sk-...
supabase secrets set ANTHROPIC_API_KEY=sk-ant-...
supabase secrets set GEMINI_API_KEY=AI...

# Optional: ZoomInfo
supabase secrets set ZOOMINFO_USERNAME=...
supabase secrets set ZOOMINFO_PASSWORD=...

# Optional: mock mode for testing without real API keys
supabase secrets set AI_MOCK_MODE=true
supabase secrets set ZOOMINFO_MOCK_MODE=true
```

> **Note:** AI keys can also be configured at runtime by an admin through the Settings → AI Engine modal in the app. These are stored in the `ces_settings` table and take priority over server-side secrets.

## 6. Frontend Build & Deploy

### 6.1 Clone and Install

```bash
git clone -b v2 https://github.com/sivac-xinu/ces-lead-generator.git
cd ces-lead-generator
npm install
```

### 6.2 Configure Environment

```bash
cp .env.example .env
```

#### Option A: Supabase Backend (default)

```
VITE_DB_BACKEND=supabase
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_ANON_KEY
```

#### Option B: Custom REST Backend

```
VITE_DB_BACKEND=rest
VITE_API_URL=https://your-api-server.com
VITE_SUPABASE_ANON_KEY=your-jwt-token
```

> **Note:** When `VITE_DB_BACKEND=rest`, the app uses REST adapter implementations (`src/lib/db-rest.ts`, `auth-rest.ts`, `api-rest.ts`). You must build a backend server that implements the API contract documented in those files. The `VITE_SUPABASE_ANON_KEY` value becomes your auth token.

### 6.3 Run Tests

```bash
npm run test          # Unit tests (vitest)
npm run typecheck     # TypeScript check
npm run lint          # ESLint
npm run test:e2e      # E2E tests (Playwright, needs dev server)
```

### 6.4 Build

```bash
npm run build
```

This produces a `dist/` folder with the static SPA. The build script also copies `index.html` to `404.html` for SPA routing on static hosts.

### 6.5 Deploy to GitHub Pages

The `v2` branch is configured to deploy to GitHub Pages automatically via GitHub Actions.

To set up for a new repo:
1. Push the `v2` branch to your GitHub repo
2. Go to repo → **Settings → Pages**
3. Set **Source** to "GitHub Actions"
4. The workflow in `.github/workflows/deploy.yml` (if present) or a manual deploy will handle it

For **manual GitHub Pages deploy**:
```bash
# Build first
npm run build

# Use gh-pages package
npx gh-pages -d dist -b v2
```

### 6.6 Deploy to Other Static Hosts

The `dist/` folder is a standard static SPA. Deploy it to:
- **Netlify**: Drag-and-drop `dist/` or connect to git
- **Vercel**: `vercel --prod` in the project root
- **AWS S3 + CloudFront**: Upload `dist/` to an S3 bucket
- **Any web server**: Copy `dist/` contents to the web root

> **Important:** Update the Auth **Site URL** and **Redirect URLs** to match your deployed frontend URL.

## 7. Post-Deploy Steps

### 7.1 Verify the Setup

**For Supabase backend:**
1. Open the deployed URL
2. Sign up for a new account
3. Check that you see the "pending approval" screen
4. In Supabase SQL Editor, approve yourself (see [First Admin User](#42-first-admin-user))
5. Refresh the app — you should see the Lead Discovery page

**For REST backend:**
1. Ensure your backend server is running and accessible
2. Update `VITE_API_URL` in `.env` to point to your server
3. Rebuild: `npm run build`
4. Open the deployed URL and sign up (your server must handle `/api/auth/signup`)
5. Approve the user in your database
6. Refresh the app — you should see the Lead Discovery page

### 7.2 Configure AI Provider (Required for Intelligence)

Without an AI provider, the Intelligence modal will fall back to local rules (less detailed).

**Option A — Via the app UI (recommended):**
1. Log in as admin
2. Go to **Settings → AI Engine**
3. Add at least one provider key (OpenRouter is easiest — get a key at [openrouter.ai](https://openrouter.ai))

**Option B — Via Supabase secrets:**
```bash
supabase secrets set OPENROUTER_API_KEY=sk-or-...
```

### 7.3 Verify Edge Functions

In Supabase Dashboard → **Edge Functions**, check that all 3 functions show as "Deployed" and healthy.

## 5a. REST Backend API Contract

> **Skip this section** if using `VITE_DB_BACKEND=supabase` (default).

When `VITE_DB_BACKEND=rest`, the frontend expects your backend server to implement these endpoints. All endpoints expect `Authorization: Bearer <token>` header.

### Database Endpoints (REST DB Adapter)

| Method | Endpoint | Description |
|--------|----------|-------------|
| `GET` | `/api/leads` | List all leads |
| `POST` | `/api/leads` | Create a lead |
| `PATCH` | `/api/leads/:id` | Update a lead |
| `DELETE` | `/api/leads/:id` | Delete a lead |
| `GET` | `/api/contacts` | List contacts (query: `?lead_id=`) |
| `POST` | `/api/contacts` | Create a contact |
| `DELETE` | `/api/contacts/:id` | Delete a contact |
| `GET` | `/api/call-logs` | List call logs |
| `POST` | `/api/call-logs` | Create a call log |
| `PATCH` | `/api/call-logs/:id` | Update a call log |
| `DELETE` | `/api/call-logs/:id` | Delete a call log |
| `GET` | `/api/solutions` | List solutions |
| `POST` | `/api/solutions` | Create a solution |
| `PATCH` | `/api/solutions/:id` | Update a solution |
| `DELETE` | `/api/solutions/:id` | Delete a solution |
| `GET` | `/api/profiles` | List profiles (query: `?id=`) |
| `PATCH` | `/api/profiles/:id` | Update a profile |
| `GET` | `/api/pain-points` | List pain point catalog |
| `POST` | `/api/pain-points` | Create a pain point |
| `PATCH` | `/api/pain-points/:id` | Update a pain point |
| `DELETE` | `/api/pain-points/:id` | Delete a pain point |
| `GET` | `/api/settings` | Get global settings (returns `{ ai_keys }`) |
| `PATCH` | `/api/settings` | Update global settings |
| `POST` | `/api/audit` | Insert audit log entry |

### Auth Endpoints (REST Auth Adapter)

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/api/auth/signup` | Register new user. Body: `{ email, password, firstName?, lastName? }` |
| `POST` | `/api/auth/login` | Sign in. Body: `{ email, password }`. Returns `{ access_token, refresh_token, user }` |
| `POST` | `/api/auth/logout` | Sign out (requires Bearer token) |
| `GET` | `/api/auth/me` | Get current user from token. Returns `{ id, email, user_metadata }` |
| `POST` | `/api/auth/refresh` | Refresh token. Body: `{ refresh_token }` |

### API Endpoints (REST API Adapter)

| Method | Endpoint | Description |
|--------|----------|-------------|
| `POST` | `/api/functions/ai-proxy` | AI proxy. Body: `{ body: { prompt, provider?, model?, maxTokens? } }` |
| `POST` | `/api/functions/zoominfo-proxy` | ZoomInfo proxy. Body: `{ body: { action, query?, domain? } }` |

### Response Format

All endpoints should return JSON. Errors should follow: `{ error: "message" }`

See the adapter files for full contract details:
- `src/lib/db-rest.ts` — database operations
- `src/lib/auth-rest.ts` — authentication
- `src/lib/api-rest.ts` — Edge Function replacements

## 10. Troubleshooting

### "API key not configured" error in Intelligence modal
→ Set at least one AI provider key via Settings → AI Engine (admin) or via `supabase secrets set`.

### "Edge Function not found" error
→ Deploy the Edge Functions. See [Section 5](#5-edge-functions-deployment).

### Users can't see leads / "permission denied"
→ Verify RLS policies are applied. Run the Step 3 SQL from [Section 3.2](#32-run-the-full-schema-sql).

### Sign-up creates no profile row
→ Verify the `handle_new_user()` trigger exists. Run:
```sql
select trigger_name from information_schema.triggers
where event_object_table = 'users' and trigger_schema = 'auth';
```

### Redirect loop after login
→ Check that the Supabase Auth **Site URL** matches your deployed frontend URL.

### 404 on page refresh (GitHub Pages)
→ The build copies `index.html` to `404.html` for SPA routing. Verify this file exists in `dist/`.

### OpenRouter 429 rate limit errors
→ Free OpenRouter models have strict rate limits. Add a small credit balance at openrouter.ai or switch to a paid model.
